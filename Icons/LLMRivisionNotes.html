📘 Generative AI & LLMs – Revision Notes

1. Generative AI Essentials

1.1 What is Generative AI?

  • Definition: Creates new content (text, images, music, code) that never existed before, by learning patterns from training data.
  • Analogy: Chef tastes 10,000 soups → invents a brand‑new soup that “tastes right”.

1.2 Generative vs. Discriminative AI

Example task“Draw a cat that doesn’t exist”“Is this a cat or a dog?”

When to use: Generative → need new content; Discriminative → need recognition/classification.

1.3 LLMs vs Other AI Model Types

  • LLM (GPT‑4, Claude): Specialised in text – understands, generates, reasons. Limitation: hallucinations, no vision/sound (unless multimodal).
  • Other models: For images (Diffusion), audio (Whisper), etc.

1.4 Key Use Cases

i. Intelligent Chatbots

ii. Document Understanding (RAG)

RAG = Retrieval‑Augmented Generation – reduces hallucinations, allows citations.
Steps: 1. Break documents into chunks. 2. Embed question. 3. Search similar chunks. 4. Retrieve relevant chunk. 5. Feed prompt Context + Question to LLM. 6. Answer with citation.

iii. Coding Assistants

flowchart TD Dev["Developer types: def calculate_average(numbers):"] --> Context["Assistant sees context"] Context --> LLM["LLM predicts next tokens: 'total = sum(numbers)'"] LLM --> Suggestion["Suggestion appears in grey"] Suggestion --> Choice{"Developer action?"} Choice -- Tab --> Accept Choice -- Keep typing --> Reject Choice -- Ignore --> Nothing

iv. Automation & Decision Support

Pattern: Classify → Extract → Decide → Act. Used in customer support, fraud detection, etc. LLM powers classification, extraction, drafting.

2. Large Language Model Fundamentals

2.1 How LLMs Work (No Math)

  • Core idea: Next‑token prediction (super‑powered autocomplete).
  • Analogy: Friend says “The capital of France is…” → you think “Paris”.
  • Attention: Each word “looks back” at previous words to decide which matter most.
flowchart LR Input["Input tokens"] --> Attention["Attention layers"] --> Predict["Predict next token"] --> Append["Append to context"] --> Loop["Repeat"]

2.2 Tokens, Tokenization, Embeddings

  • Token: piece of a word or punctuation. Example: "unhappiness" → ["un", "happiness"]
  • Embedding: a vector (list of numbers) capturing meaning.
  • Analogy: map coordinates: “king”, “queen”, “prince” close together.
flowchart LR Text["Text: 'Hello world'"] --> Tokenizer["Tokenizer"] --> Tokens["Tokens: ['Hello', 'world', '!']"] Tokens --> IDs["Token IDs: [1234, 5678, 99]"] IDs --> Embedding["Embedding: [0.12, -0.45, ...]"]

2.3 Context Windows and Memory Limits

  • Context window: max tokens the model can see at once (short‑term memory).
  • Limited by computational cost O(n²). Typical sizes: GPT‑3.5 (4K), GPT‑4 Turbo (128K), Claude 3 (200K), Gemini 1.5 Pro (2M experimental).
  • Exceeding limit → oldest tokens dropped (model forgets). Tip: Use RAG for long documents.

3. Embedding & Vector Basics

3.1 What embeddings represent

Definition: A list of numbers capturing meaning. Analogy: coordinates on a map – similar meanings are close.

3.2 Vector Similarity & Distance Metrics

  • Cosine similarity: measures angle (direction). Best for semantic search (ignores length).
  • Euclidean distance: straight‑line distance. Use when exact numeric values matter.

4. Prompt Engineering

4.1 Prompting Basics

  • Prompt: instruction/input given to AI.
  • Prompt engineering: skill of writing prompts to get best output.
  • Why it matters: models are literal pattern‑matchers – vague input → vague output.

4.2 Zero‑shot, One‑shot, Few‑shot Prompting

Technique# ExamplesBest forAdvantageDisadvantage
Zero‑shot0simple, well‑known tasksshort prompt, fastmay miss nuance
One‑shot1slightly tricky tasksvery little extra costonly one pattern
Few‑shot2–5complex or unusual taskshigh accuracy, teach new patternslonger prompt, more tokens

4.3 Chain‑of‑Thought (CoT) and Tree‑of‑Thoughts (ToT)

Chain‑of‑Thought (CoT)Tree‑of‑Thoughts (ToT)
How it worksSingle linear reasoning pathMultiple parallel reasoning paths, evaluated and combined

4.4 Structured Prompting, Guardrails, Role Prompts

  • Structured prompting: Use JSON, XML, bullet points to guide format.
  • Guardrails: constraints for safety, tone, factuality (e.g., “If unknown, say ‘I don’t know’”).
  • Role prompts (personas): “Act as a [profession/character]” changes vocabulary, tone, perspective.

Complete structured prompt template:

[ROLE] You are a helpful coding assistant specialising in Python.
[INSTRUCTION] Generate a function that returns the average of a list.
[FORMAT] Return only the code block, no extra text.
[GUARDRAILS] - If list empty, return None. - Use only built‑ins.
[USER INPUT] List: [10, 20, 30]

✅ Final Mental Model (Summary)

  • Generative AI = creates new content (chef inventing dish)
  • Discriminative AI = categorises existing things (security guard)
  • LLM = generative AI for text – predicts next token
  • Tokens = pieces of text; embeddings = numeric vectors of meaning
  • Context window = short‑term memory (4K–200K tokens)
  • Decoding parameters (temp, top‑p, top‑k) = creativity vs consistency dials
  • Roles (system/user/assistant) = structure conversation
  • Semantic search = uses embeddings + cosine similarity
  • Vector database = fast similarity search at scale
  • RAG = retrieve chunks (embedding model) + generate answer (LLM)
  • Prompt engineering = zero/many‑shot, CoT/ToT, guardrails, personas
